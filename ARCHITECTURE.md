# Architecture

This document describes the architecture of Shaheer Ali's portfolio site — a single-page scrolling portfolio built with Next.js 15, TypeScript, and Tailwind CSS 4.

---

## High-Level Overview

The project is a **statically-generated site** built with Next.js App Router. The home page (`/`) composes multiple sections (Hero, About, Engineering, Skills, Experience, Projects, Education, Footer) with anchor-based navigation. Featured projects have **dedicated case-study pages** at `/projects/[slug]`, pre-rendered at build time via `generateStaticParams`. All pages are pre-rendered — no server-side rendering or dynamic routing.

```
Browser Request → Vercel Edge → Static HTML (pre-rendered at build) → Client hydrates
```

---

## Framework & Rendering

- **Next.js 15** with App Router (`src/app/`)
- **Static generation (SSG):** every page is built at `next build` time. Project pages use `generateStaticParams` (all 10 projects statically generated; unknown slugs 404).
- **One API route:** `/api/contact` handles the contact form via Resend email delivery (Vercel serverless), with server-side validation and in-memory rate limiting.
- **Client Components:** section components use `"use client"` because they import Framer Motion or React state (`useState`). `contact-form.tsx` is a client component for form interactivity.
- **Server Components:** `page.tsx`, `about.tsx`, `engineering-highlights.tsx`, `footer.tsx`, `ui/button.tsx`, `ui/badge.tsx`, and the project detail page are server components.

---

## Routing

| Route | File | Rendering |
|-------|------|-----------|
| `/` | `src/app/page.tsx` | Static (SSG) |
| `/projects/[slug]` | `src/app/projects/[slug]/page.tsx` | Static (SSG, `generateStaticParams`) |
| `/api/contact` | `src/app/api/contact/route.ts` | Dynamic (serverless) |

Additional static files generated by Next.js conventions:
- `/sitemap.xml` → `src/app/sitemap.ts` (includes home + all project pages)
- `/robots.txt` → `src/app/robots.ts`
- `/icon.svg` → `src/app/icon.svg`

Home navigation is anchor-based (`/#about`, `/#engineering`, etc.). Project pages use file-based routing with a `slug` param.

## Component Architecture

```
src/components/
├── navbar.tsx                    # Client — sticky nav, mobile menu, active section highlight, theme toggle
├── hero.tsx                      # Client — hero section with CTAs
├── about.tsx                     # Server — background, focus, strengths, career direction
├── engineering-highlights.tsx    # Server — 6 capability cards
├── skills.tsx                    # Client — categorized skill cards
├── experience.tsx                # Client — timeline of work history
├── projects.tsx                  # Client — featured (case-study) + additional project cards
├── education.tsx                 # Client — education section
├── footer.tsx                    # Server — contact form + copyright
├── contact-form.tsx              # Client — contact form with API integration
├── theme-provider.tsx            # Client — next-themes provider wrapper
├── theme-toggle.tsx              # Client — dark/light mode toggle button
└── ui/
    ├── button.tsx                # Server-compatible — shadcn-style Button with CVA
    └── badge.tsx                 # Server-compatible — shadcn-style Badge with CVA
```

**Client vs Server breakdown:**
- **Server Components (8):** `page.tsx`, `about.tsx`, `engineering-highlights.tsx`, `footer.tsx`, `ui/button.tsx`, `ui/badge.tsx`, plus the project detail page (`app/projects/[slug]/page.tsx`)
- **Client Components (9):** `navbar.tsx`, `hero.tsx`, `skills.tsx`, `experience.tsx`, `projects.tsx`, `education.tsx`, `contact-form.tsx`, `theme-toggle.tsx`, `theme-provider.tsx`

The `"use client"` directive is required for any component using:
- `useState` (navbar, projects, contact-form)
- Framer Motion `motion.*` components (hero, skills, experience, projects, education)
- `useTheme` hook (theme-toggle)
- Event handlers (contact-form)

## Data / Content Architecture

All content lives in typed TypeScript files under `src/data/`:

```
src/data/
├── site-config.ts    # Global site metadata, headline, focus, positioning
├── about.ts          # AboutEntry + Highlight[] — background, focus, strengths, highlights
├── skills.ts         # SkillCategory[] — skills organized by category
├── experience.ts     # ExperienceEntry[] — work history timeline
├── projects.ts       # Project[] + derived featuredProjects / moreProjects + getProjectBySlug
├── education.ts      # EducationEntry[] — education records
└── articles.ts       # Article[] — technical writing model (currently empty)
```

Each data file exports typed interfaces and arrays. Components import and map over these arrays — no content is hardcoded in JSX. The `Project` type includes a `slug` plus optional case-study fields (`overview`, `problem`, `solution`, `architecture`, `responsibilities`, `challenges`, `keyFeatures`, `impact`). The project detail page reads `getProjectBySlug(slug)` and renders any provided sections.

**Adding new content:** edit the relevant `src/data/*.ts` file. The component will render it automatically.

## Styling Architecture

- **Tailwind CSS 4** via `@tailwindcss/postcss` (PostCSS plugin)
- **CSS-based theme** in `src/app/globals.css` using `@theme inline` and CSS custom properties
- **Dark/Light mode** via CSS class (`.dark`) toggled by `next-themes`
- **No Tailwind config file** — all theme tokens are defined in CSS using `@theme inline` and `:root` / `.dark` selectors
- **Utility class merging** via `cn()` helper (`clsx` + `tailwind-merge`) in `src/lib/utils.ts`

**CSS Variables (design tokens):**
```
--background, --foreground
--card, --card-foreground
--primary, --primary-foreground
--muted, --muted-foreground
--accent, --accent-foreground
--border
--radius
--font-sans
```

## UI Component Architecture

Base UI primitives follow the shadcn/ui pattern:
- **class-variance-authority (CVA)** for variant-based styling
- **tailwind-merge** for class deduplication
- **Forwarded refs** for composability

Currently two primitives exist: `Button` and `Badge`. More can be added following the same pattern in `src/components/ui/`.

Section-level components (Navbar, Hero, Skills, etc.) live directly in `src/components/` and are imported only by `page.tsx`.

---

## Animation Architecture

- **Framer Motion** for scroll-triggered animations
- Pattern: `initial={{ opacity: 0, y: 20 }}` → `whileInView={{ opacity: 1, y: 0 }}` with `viewport={{ once: true }}`
- Hero uses staggered children animation (`staggerChildren: 0.12`)
- `prefers-reduced-motion` is respected via CSS (`globals.css`) which disables all transitions and transforms
- No animation library is used for the Navbar menu — it uses CSS `max-h` transitions

## External Integrations

| Integration | Purpose | Required |
|-------------|---------|----------|
| **Resend** | Email delivery for contact form | No — without `RESEND_API_KEY` the API returns 503 and the form shows an error |

The portfolio is otherwise a static site with no:
- Databases
- Authentication
- Third-party analytics
- CMS

All external links are outbound (GitHub, LinkedIn, app store links, project portals).

## Contact API

`/api/contact` (POST) flow:

1. **Rate limiting** — in-memory, 3 requests / 60s per IP → returns 429
2. **Parse JSON** body; reject invalid JSON → 400
3. **Server-side validation** — required name/email/message, email format, min message length → 400
4. **Sanitize** inputs (trim + length caps) to bound storage/email payload
5. **Check `RESEND_API_KEY`** — return 503 if not configured
6. **Send via Resend** — errors → 500; success → 200

Note: in-memory rate limiting is per-serverless-instance (reset when the function cold-starts). Adequate for a low-traffic portfolio; a shared store would be needed for harder guarantees.

## Key Architectural Decisions

1. **Static-first:** only the contact form API is server-side, everything else is static and fast
2. **Multi-page:** home scroll + dedicated static project detail pages for featured work
3. **Data-driven content:** content in `src/data/`, components just render data; case-study fields are optional per project
4. **Tailwind v4 CSS config:** no `tailwind.config.ts`, all tokens in `globals.css`
5. **Client components only where needed** — About/Engineering/Footer are server components; only sections with animation/state are client components
6. **Dark mode by default:** `next-themes` with `defaultTheme="dark"`
7. **Optional contact form:** Resend integration disabled gracefully without env var; validated + rate-limited
8. **Reduced motion support:** CSS media query disables all animations for users who prefer reduced motion
